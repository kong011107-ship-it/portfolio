공고를 늘려도 입사자가 늘지 않을 때 무엇을 볼 것인가 — 유입이 아니라 이탈 지점을 데이터로 특정했습니다.

시기 성수기 인력 충원 대응 범위 원인 분석 · 개선안 수립 · 적용 대상 상담원 직군 한정

배경

지원자의 절반 가까이가 면접 단계에서 사라졌습니다

  • 주력 사업인 항공사 고객지원 상담센터의 성수기 충원이 시급했습니다. 공고와 채널을 늘렸지만 최종 입사자 수가 따라오지 않았습니다.
  • 이탈이 어디서, 왜 생기는지를 체감이 아니라 데이터로 확인하는 것이 먼저라고 판단했습니다.

실행

포기 사유를 직접 수집해 원인을 특정했습니다

면접 포기자의 사유를 모아보니 타사 합격이 다수였습니다. 비숙련 직군 지원자는 즉시 일자리가 필요한 층인데, 회사는 브랜딩 방침에 따라 안내를 2~3일 뒤에 보내고 있었습니다. 먼저 연락한 회사가 데려가는 구조였습니다.

사업의 언어

성수기까지 인원을 채운다

충원이 늦으면 상담센터 운영 자체가 흔들립니다.

조직의 언어

브랜딩 방침은 유지한다

안내 시점을 두는 데는 이유가 있었습니다.

지원자의 언어

당장 일할 곳이 필요하다

2~3일은 지원자가 다른 회사로 옮겨 가는 시간이었습니다.

전사 방침은 그대로 두고 상담원 직군에 한해 예외를 설계했습니다. 정책을 부정하는 대신 적용 범위를 조정하는 쪽을 택했습니다.

02 · 프로젝트 2 — 현대엘리베이터㈜ 인재확보팀

반복되는 채용 운영을 하나의 시스템으로 만들었습니다

개인정보 제약 속에서도 AI를 활용해 도구를 설계했습니다.

기간 3주 · 업데이트 60회 범위 기획 · 설계 · 개발 · 매뉴얼화 단독 수행 결과 경영지원본부 AI 업무 혁신 우수상

배경

회사 전체가 LLM 활용에 선을 긋고 있었습니다

  • 사내 개인정보 유출 사건 이후 운영 업무에서의 LLM 활용이 전면 제한됐습니다. 비용과 의사결정 구조를 이유로 채용 AX 자체를 회의적으로 보는 시선도 있었습니다.
  • 그러나 채용 절차마다 도구와 데이터가 흩어져 같은 정보를 반복 입력하고 다시 대조해야 했고, 진행 단계는 문서가 아니라 담당자의 기억에 남아 있었습니다.

실행

LLM을 워크플로우에 넣는 대신, LLM으로 도구를 만들었습니다

업무를 Task 단위로 분해하고 6개 질문(정보의 출처 / 사람의 판단 지점 / 반복 작업 / 오류 발생 지점 / 검증 방식 / 기록 위치)으로 경계를 먼저 그었습니다. 판단과 저작은 사람이, 반복·대조·표준화는 도구가 하도록 나눴습니다. 그리고 HTML로 데이터를 처리하면 외부 서버 전송이 없다는 점을 확인해, 설계 단계에만 AI를 쓰는 오프라인 도구로 방향을 잡았습니다.

Track A — 팀을 향해

RE:CRUIT 운영 콘솔 · 도구 6종

채용 문의 답변 도구부터 시작해, 콘솔을 공용 데이터 허브로 두고 도구를 채용 흐름대로 연동했습니다.

  • 면접 일정 편성 · 50분 → 7.5분
  • 입사 프로세스 도우미 · 40분 → 11.5분
  • 입사구비서류 검증 · 40분 → 15분
  • 인사기록표 복붙마법사 · 15분 → 3분
  • 채용 문의 답변 도우미 · 5분 → 2분

Track B — 현업을 향해

AI 에이전트 3종

MS Copilot Agent Studio로 설계. 대신 써주는 것이 아니라 표준화만 자동화해, 정보의 주인을 현업으로 남겼습니다.

  • 직무 가이드북 생성 · 1주 → 3일 · 누적 33개 직무
  • 이력서 심의대장 · 10분 → 2분 (1인당)
  • AI 모의면접 · 기획·설계 완료, 실행 보류

03 · 프로젝트 3 — ㈜에이아이씨엑스 HR팀 · 2024.12

채용 킥오프 프로세스 설계

절차를 늘리면 일이 늘어난다 — 그래서 늘리지 않고, 앞단으로 옮겼습니다. 총소요시간은 오히려 줄었습니다.

범위 설계 · 전사 공지 · 정착 대상 채용을 요청하는 전 부서 상태 조직 내 필수 절차로 정착

배경

채용이 메신저 한 줄에서 시작되고 있었습니다

  • 재택근무가 기본인 조직에서 개발 조직이 신설되며 신규 공고가 급증했습니다. 현업이 메신저로 "이런 사람 뽑아주세요"라고 보내면 채용이 시작됐고, 필요한 정보가 처음부터 빠져 있었습니다.
  • 담당자가 다시 묻고, 답이 늦고, 또 묻는 재문의가 반복되며 채용 맥락과 인재상이 담기지 않은 공고가 나갔습니다.

실행

단계를 추가한 것이 아니라, 순서를 바꿨습니다

기존

메신저 요청→ 담당자 추가 문의→ 답변 대기→ 재문의→ 공고 작성

개편

화상회의 킥오프→ 표준 요청서→ 공고 게시
  • 뒤에서 반복되던 문답을 앞의 30분에 몰아넣고, 채용 사유 · 목표 시기 · 인원 · 전형 절차를 회의에서 반드시 합의하는 항목으로 고정했습니다.
  • 전사 공지를 문제 상황 → 개편 필요성 → 변경된 진행 방식 순으로 구성했습니다. 새 규칙을 먼저 알리면 규제로 읽히고, 문제를 먼저 알리면 해결책으로 읽힙니다.

해소

채용 맥락과 인재상이 공고에 반영

정착

조직 내 필수 절차로

별도 저항 없이 전 부서 적용

현업 입장에서 늘어난 것은 회의 한 번이고, 줄어든 것은 며칠간의 문답이었습니다. 반대가 나오지 않은 이유는 설득을 잘해서가 아니라 실제로 각자의 일이 줄었기 때문이라고 봅니다.
